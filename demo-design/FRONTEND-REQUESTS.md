## 0. 먼저 알아 둘 것

- **고객/개발자 전환 버튼은 시연용입니다. 실제 앱에는 만들지 마세요.** 역할은 `project.my_role`(project_members.role)로 정해지고 화면에서 바꿀 수 없습니다. 데모에서는 점선 테두리 + "시연용" 표시로 구분해 두었습니다.
- 팀 결정
  1. 초안 핀은 초안에만 둡니다. 배포본으로 옮기거나 다시 찾지 않습니다.
  2. 검수 요청은 묶음 제출. 개발자가 요청마다 반영 설명을 쓰고 **배포 미리보기에 "고친 위치"를 다시 찍습니다.** 고객은 그 위치를 보며 검수합니다.
  3. 검수할 사이트는 처음 연결한 배포 주소로 고정. 검수 요청에서 주소를 다시 받지 않습니다.

## 1. 색과 강조 규칙 (모든 화면 공통)

| 단계 | 쓰는 곳 | 모양 |
| --- | --- | --- |
| 보라 채움 | 사이트 위 핀, 지금 보고 있는 핀 번호, "지금 할 일" 카드, 검수 요청의 "반영 위치 찍기", 핀 모드 켜짐 | 화면마다 하나만 |
| 검정 채움 | 영역의 주 버튼 하나 (패널 아래 버튼, 대화상자 확인, 툴바의 "검수 요청 만들기") | 영역마다 하나만 |
| 외곽선 | 카드·목록에서 반복되는 버튼 (확인 시작, 작업 시작, 검수 요청에 담기, 개발자 초대) | 흰 바탕 + 회색 선 |
| 연한 색 | 목록의 핀 번호(연보라 바탕 + 보라 글자), AI 배지(회색), 태그, 안내 상자, 내 말풍선 | 회색·연보라 |
| 빨강 | "내 차례"(칩 대신 빨간 점 + 글자), 내 차례인 핀의 점, 알림 종 숫자·새 알림 점 | 작은 점 |

- 같은 강한 색이 한 영역에 두 번 이상 나오지 않게 합니다. 예: 요청 관리 카드마다 검정 버튼 → 외곽선, 위치를 찍어야 할 카드가 여럿이면 첫 번째만 보라 채움.
- 링크성 버튼("변경", "배포본에서 반영 위치 보기")은 검정 글자 + 밑줄.
- 답글 보내기 버튼은 회색, 마우스를 올리면 검정 (결정 버튼과 겹치지 않게).
- 채팅 버튼 숫자는 전체 메시지 수라서 회색 배지.

## 2. 백엔드 없이 지금 할 수 있는 것

### 작업 화면 `/projects/[id]/viewer`
- **미리보기를 브라우저 틀로**: 왼쪽 위 뒤로/앞으로 동그란 버튼(사이트 안 이동 기록), 틀 위쪽 점 세 개 + 주소창. 주소창을 누르면 페이지 목록(페이지마다 핀 개수). 새로고침·화면 크기·완료 보기·전체 화면은 틀 오른쪽 위.
- **아래 도구 막대**: 체험(커서) · 핀 남기기(말풍선, 켜지면 보라 원) | 확대 `+ 100% −` (50~150%, iframe과 핀 레이어를 한 상자에서 함께 확대) | "화면 맞춤". 단축키 `V`·`C`·`F`·`Esc`.
- **틀 아래 오른쪽 시각**: 초안은 "초안 생성 · N일 전"(`draft.updated_at`), 배포본은 "마지막 배포 · N일 전"(백엔드 대기).
- **핀**: 38px. 상대 차례인 핀은 연보라, 내 차례인 핀은 빨간 점, 완료는 회색. 작은 점으로 줄이지 않습니다.
- **초안/배포본 전환**(상단바 사이트 선택): 배포 주소가 생겨도 초안을 다시 볼 수 있게. 배포 전에는 배포본 선택을 막고 안내.
- **오른쪽 패널**: "이 페이지 요청 N" → "지금 할 일" 카드 1개(내 차례 중 첫 번째) → 나머지 한 줄씩 → "다른 페이지 요청 N개 보기". 페이지에 핀이 없으면 빈 상태 문구.
- **요청 상세**: 상태 `n/5`, "내 차례", 채팅에 공유 버튼, 요청 원문 + **AI 개발 요청 정리(`ai_summary`)**, 대화(상태 변경은 가운데 작은 글씨), 역할별 결정 버튼.
  - 개발자: 대기 → "확인 시작", 확인 중 → "작업 시작", 작업 중 → "검수 요청에 담기"
  - 고객(검수 대기): "반영 내용"(개발자 설명 + AI 쉬운 풀이 + "배포본에서 반영 위치 보기"), 재수정 요청(사유 필수) / 승인하기
- **위치 확인 필요**: 핀 자리를 못 찾으면 주황 안내 + "위치 다시 지정"(같은 사이트 안, `PATCH /pins/{id}/location`).
- **내 답글 수정·삭제**: 말풍선에 마우스를 올리면 "수정 · 삭제". 빈 내용 저장 막기, 삭제는 한 번 더 확인, 삭제 후 "삭제된 댓글입니다", 해결된 요청은 수정 불가.
- **새 요청 입력**: 예시 칩("색을 바꾸고 싶어요" 등).
- **상단바**: 배포 주소 칩(개발자는 눌러서 변경, 연결 전에는 "배포 연결"), 연결 전 "코드 받기", 참여자 아바타, 고객에게 "초대" 버튼.
- **완료 보기 토글**: 해결된 핀도 회색으로 표시.

### 배포 연결 대화상자 (개발자)
- 주소 입력 + 핀 스크립트 코드 복사.
- 검증: 빈 값, 공백, `http://`, 아이디·비밀번호가 든 주소는 거절. **경로는 빼고 origin만 저장**하고 그렇게 했다고 알려 주기(FE#80). 이미 같은 주소면 안내. 복사 실패도 안내.

### 핀 스크립트가 없는 배포 사이트 (FE#80)
- 2초 안에 연결되지 않으면 핀 모드를 막고 상단에 주황 안내. 개발자에게는 "설치 방법"(배포 연결 대화상자), 고객에게는 "개발자에게 설치를 요청해 주세요". 좌표만으로 핀을 찍는 대체 방식은 없앱니다.

### 요청 관리 `/projects/[id]/requests`
- "내 차례만" 토글, 열마다 "개발자 차례/고객 차례", 카드에 "내 차례"(빨간 점), 사이트 필터(초안/배포본, 백엔드 대기).
- 카드 버튼은 외곽선. 작업 중 카드는 "검수 요청에 담기" → 작업 화면의 검수 요청 만들기로 이동하며 그 요청을 미리 선택.
- 툴바(개발자): "검수 요청 만들기 · N" (검정, 이 화면의 유일한 검정 버튼).

### 프로젝트 목록 `/projects`
- 검색, 카드에 참여자 아바타 · "내 차례 N"(빨간 점) · 개발자가 없으면 "개발자 초대"(외곽선).

### 초안 생성
- **프로젝트 이름 입력칸** (지금은 설명 첫 줄을 이름으로 씀).
- 상단 긴 설명 문구 없이 제목만.
- 생성 중: 사이트가 조립되는 장면 + 단계 목록, 끝나면 핀이 떨어지는 안내.
- 생성 실패: 주황 상자 "초안을 만들지 못했어요" + "다시 시도" / "내용 고치기"(적은 내용 유지).
- 결과: "다음 단계"(핀으로 요청 → 개발자 초대 → 검수), 주 버튼 "작업 화면에서 요청 남기기", "다시 만들기", "코드 받기 (ZIP)". GitHub 저장소 만들기는 없음.

## 3. 백엔드 작업 후 할 것

| 할 일 | 기다리는 백엔드 작업 |
| --- | --- |
| **검수 요청 만들기**: 작업 화면에서 배포본을 띄운 채 패널에서 작업 중 요청을 고르고(체크), 요청마다 반영 설명 + "배포본에서 반영 위치 찍기"(사이트를 눌러 위치 저장). 검수할 사이트는 연결된 주소로 고정 표시. 설명·위치가 빠지면 카드 강조, 고른 게 없으면 버튼 비활성, 작업 중 요청이 없으면 빈 상태 | `review-requests`에서 `deployment_url` 제거, `items[].location` |

| 배포본에서 검수 위치를 흰 테두리 핀으로 표시, 고객 검수 | `latest_review_item.location` |
| 초안 핀은 초안에서만, 배포본 핀은 배포본에서만 | `pins.source` |
| 이메일 대신 이름, 회원가입 이름 칸 | `users.name` |
| 새 요청·승인 알림 문구 | `change_created`, `change_resolved` |
| "마지막 배포 · N일 전" | `deployment_updated_at` |
| 프로젝트 카드 "초안만 있어요", "내 차례 N" 한 번에 받기 | `has_draft`, `my_turn_count` |

## 4. 하지 않는 것

받은 초대 목록·거절, 이메일 초대, 마지막 활동 시각, 초안 페이지 목록, 프로필 사진 핀, 고객/개발자 전환 버튼. (이미 있는 로그아웃 버튼은 그대로 둡니다. 데모에만 없습니다.)
