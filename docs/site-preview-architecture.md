# 사이트 미리보기와 핀 구현 방식 (제안)

> 상태: **제안**. CLAUDE.md "결정이 필요한 것"의 _외부 배포 사이트 미리보기 방식_, _AI 초안 미리보기 렌더링 방식_ 에 대한 안입니다. 팀에서 확정하면 이 줄을 바꿔 주세요.

## 요약

외부 배포(Vercel)를 쓰되, **AI가 만드는 사이트 템플릿에 RE:SPEC 핀 스크립트(`respec-pin.js`)를 기본으로 넣고**, 워크스페이스(부모)와 iframe(사이트)이 `postMessage`로 통신합니다.

- cross-origin iframe이면 부모는 안쪽 DOM, 클릭, 경로를 읽을 수 없습니다. 하지만 iframe **안에서 도는 스크립트**는 다 읽을 수 있으므로, 그 스크립트가 결과만 부모에 전달하면 됩니다.
- 사이트를 우리 AI가 생성하므로 스크립트 삽입, iframe 허용 헤더, 핀 앵커용 속성을 템플릿 단계에서 넣을 수 있습니다.
- Vercel Comments, Marker.io, BugHerd 같은 웹사이트 코멘트 서비스도 스크립트 삽입 방식을 씁니다.

## 검토한 대안

| 방식                                        | 판단   | 이유                                                                                    |
| ------------------------------------------- | ------ | --------------------------------------------------------------------------------------- |
| 플랫폼 안에서 코드 직접 실행 (Sandpack 등)  | 비추천 | 개발자는 결국 저장소에서 작업하므로 코드가 두 군데 생김. 개발자 수정 흐름이 불편함      |
| 프록시로 같은 출처에서 띄우기               | 비추천 | Next.js 에셋 경로, CSP, 쿠키, 라우팅이 깨지기 쉬움. 해커톤 일정에 맞지 않음             |
| 투명 오버레이로 좌표만 저장                 | 폴백용 | 요소 기준 핀과 "위치 확인 필요" 판정이 불가능. 스크립트가 연결되지 않을 때만 사용       |
| **배포 사이트 + 핀 스크립트 + postMessage** | 채택안 | 개발자는 평소처럼 개발/배포, 핀은 요소 기준으로 저장 가능, 초안과 배포 단계에 같은 코드 |

## 구조

```text
[RE:SPEC 워크스페이스]  ← 핀 목록, 스레드 UI, 채팅
  └ <iframe src="https://고객사이트.vercel.app">
       └ respec-pin.js (템플릿에 기본 포함)
          - 핀 모드: 투명 레이어로 클릭을 막고 아래 요소 찾기
          - 클릭한 요소의 앵커 계산 → parent로 전송
          - 페이지 이동 감지 → parent로 전송
          - 저장된 핀을 받아 요소 위에 마커 표시
          - 요소를 못 찾으면 "위치 확인 필요"로 보고
```

### 역할 분담

- **iframe 안 스크립트**: 핀 마커 그리기(Shadow DOM으로 사이트 CSS와 격리), 클릭 가로채기, 앵커 계산과 복원, 경로 감지
- **부모(워크스페이스)**: 핀 스레드, 패널, 채팅, 모드 전환 UI, 서버 통신

핀 마커를 부모에서 그리면 스크롤, 레이아웃 밀림, 애니메이션마다 메시지 지연이 생겨 핀이 흔들리므로 마커는 iframe 안에서 그립니다.

### 메시지 규격 (초안)

```ts
// 부모 → iframe
{ type: 'respec:set-mode', mode: 'browse' | 'pin' }
{ type: 'respec:show-pins', pins }
{ type: 'respec:navigate', path, pinId } // 채팅 핀 카드 클릭 시

// iframe → 부모
{ type: 'respec:ready', version }
{ type: 'respec:path-changed', path }
{ type: 'respec:pin-created', anchor }
{ type: 'respec:pin-missing', pinId } // 위치 확인 필요
{ type: 'respec:pin-hidden', pinId } // 요소가 지금 화면에 없음 (모달, 탭 등)
```

- 양쪽 모두 `event.origin`을 검사합니다. 부모는 프로젝트에 등록된 배포 URL origin만, 스크립트는 RE:SPEC origin만 받습니다.
- 인증 토큰이나 사용자 정보는 iframe으로 보내지 않습니다. iframe 안 코드는 개발자가 고칠 수 있으므로 노출된다고 봅니다.

## 핀 저장 형식

```ts
type PinAnchor = {
  path: string; // 페이지 경로 (쿼리 포함 여부는 아래 "정할 것" 참고)
  respecId?: string; // data-respec-id 값 (1순위)
  index?: number; // 같은 respecId가 여러 개일 때 몇 번째인지
  selector?: string; // respecId가 없을 때 대체 (최후의 수단)
  textSnippet?: string; // 요소 텍스트 일부, 찾은 요소 검증용
  offset: { x: number; y: number }; // 요소 안 상대 위치 (0~1)
  fallback: { x: number; y: number }; // 페이지 좌표
  viewportWidth: number; // 찍을 당시 화면 너비
  deploymentId: string; // 찍을 당시 배포
  screenshotUrl?: string; // 핀 주변 캡처 (맥락 보존용)
};
```

- AI가 코드를 생성할 때 섹션과 컴포넌트마다 `data-respec-id`를 붙입니다. 개발자가 코드를 고쳐도 이 속성이 남아 있으면 핀이 따라갑니다.
- 재배포 후 앵커를 찾지 못하면 `fallback` 좌표에 흐리게 표시하고 **"위치 확인 필요"** 로 둡니다. 핀은 지우지 않습니다.
- 이전 버전 사이트는 저장하지 않으므로, 위치를 잃었을 때 맥락을 남기려고 핀 생성 시 스크린샷을 함께 저장합니다.

## 단계별 흐름

1. **초안 단계 (개발자 작업 전)**
   해커톤 범위는 "정해진 컴포넌트 조합"이므로 코드를 실행하지 않고 JSON 스펙을 우리 렌더러로 그립니다. `/preview/draft/:id` 같은 별도 라우트를 iframe으로 띄우고 같은 핀 스크립트를 붙입니다. `srcdoc`은 페이지 이동(경로) 개념이 없어 쓰지 않습니다.
2. **코드 전달**
   JSON 스펙을 Next.js 프로젝트 코드로 내보냅니다. 핀 스크립트, `frame-ancestors` 헤더, `data-respec-id`가 포함된 상태여야 합니다. 렌더러와 내보내기에 **같은 컴포넌트 소스**를 써서 초안 화면과 실제 코드가 어긋나지 않게 합니다. (전달 방식은 미정이지만 이 흐름에는 GitHub 저장소 생성이 잘 맞습니다.)
3. **개발 단계**
   개발자는 로컬에서 작업 → GitHub push → Vercel 자동 배포. 워크스페이스는 프로젝트에 연결된 배포 URL을 iframe으로 띄웁니다.

### 템플릿에 기본으로 들어갈 것

- `respec-pin.js`를 `async`로 로드. iframe 안일 때(`window.parent !== window`)만 동작
- `Content-Security-Policy: frame-ancestors 'self' <RE:SPEC 도메인>`
- 컴포넌트마다 `data-respec-id`
- 쇼핑몰, 예약 등은 목데이터 고정 (데이터가 바뀌면 앵커가 흔들림)

## 예상 문제와 대응

| 영역      | 문제                                                                                 | 대응                                                                       |
| --------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 앵커      | `map`으로 그린 반복 요소는 `data-respec-id`가 중복됨                                 | `index`와 `textSnippet`을 같이 저장                                        |
| 앵커      | 모달, 탭, 아코디언 안의 요소는 닫혀 있으면 DOM에 없거나 숨겨짐                       | "위치 확인 필요"와 구분해 `pin-hidden`(지금 화면에 없음) 상태를 둠         |
| 앵커      | API 데이터, 로그인 상태, 랜덤 요소로 화면이 바뀜                                     | 생성 사이트는 목데이터 고정                                                |
| 앵커      | CSS selector는 Tailwind 클래스, `nth-child` 변경에 쉽게 깨짐                         | selector는 최후의 수단, 텍스트로 검증                                      |
| 반응형    | 고객(모바일)과 개발자(PC)의 레이아웃이 다르고 `md:hidden` 같은 요소가 있음           | `viewportWidth` 저장, 뷰어에 데스크톱/모바일 너비 프리셋                   |
| 핀 모드   | `click`만 막으면 `pointerdown`, `touchstart`, hover로 동작하는 컴포넌트가 반응함     | iframe 안에 투명 레이어를 덮고 `document.elementsFromPoint()`로 요소 찾기  |
| 핀 모드   | 유튜브, 지도 같은 iframe 안의 iframe은 안쪽 요소를 읽을 수 없음                      | 해당 iframe 영역 단위로만 핀 허용                                          |
| 경로      | Next.js 클라이언트 이동은 `pushState`라 감지 이벤트가 없음                           | `pushState`/`replaceState` 감싸기 또는 Navigation API                      |
| 배포      | Vercel 미리보기 URL은 커밋마다 바뀌고 로그인 보호가 걸린 경우가 많음                 | 프로덕션 도메인 하나만 프로젝트에 연결                                     |
| 배포      | 개발자가 `frame-ancestors` 헤더를 지우면 iframe이 안 뜨는데 `onload`로는 감지 불가   | `respec:ready`를 3초 안에 못 받으면 안내 + 좌표만 저장하는 오버레이로 폴백 |
| iframe    | 구글 OAuth, 일부 결제창, 도메인 등록이 필요한 지도 API는 iframe 안에서 막힘          | 해당 동작에 "새 탭에서 열기" 안내                                          |
| iframe    | Safari 등은 iframe 안 쿠키와 저장소를 분리해서 사이트 안 로그인이 유지 안 될 수 있음 | 생성 사이트는 로그인 없이 동작하도록 구성                                  |
| 보안      | origin 검사 누락 시 다른 사이트가 가짜 핀 메시지를 보낼 수 있음                      | 양방향 origin 검사                                                         |
| 보안      | 배포 URL에 임의 주소를 등록하면 피싱 사이트를 워크스페이스에 띄울 수 있음            | 해커톤에서는 `*.vercel.app`만 허용                                         |
| 보안/성능 | 핀 스크립트가 실제 방문자에게도 로드됨, 우리 서버 장애 시 영향                       | `async` 로드, iframe 안에서만 활성화, 버전 고정                            |
| 초안      | JSON 렌더러 화면과 내보낸 코드가 다르면 초안 단계 핀이 배포 후 안 맞음               | 렌더러와 내보내기에 같은 컴포넌트 소스 사용                                |
| 이력      | 이전 버전을 저장하지 않아서 위치를 잃은 핀은 원래 화면을 알 수 없음                  | 핀 생성 시 스크린샷과 `deploymentId` 저장                                  |

## 해커톤 우선순위

1. 생성 사이트 목데이터 고정 + 반복 요소 `index`
2. 투명 레이어 방식 핀 모드 + `pushState` 감지
3. `respec:ready` 타임아웃 폴백 + 결제/로그인 "새 탭에서 열기"
4. 핀 생성 시 스크린샷 저장
5. 화면 너비 프리셋

범위 밖: 반응형 핀 위치 보정, 핀 위치 자동 복구, 초안 단계 핀을 배포 단계로 이관, 실시간 화면 동기화(스크롤, 커서 공유).

## 정할 것

- 경로 기준: `/products/3`과 `/products/4`를 같은 페이지로 볼지, 쿼리(`?tab=review`)를 경로에 포함할지
- 초안 단계 핀을 배포 단계로 넘길지
- 초안 코드 전달 방식 (GitHub 저장소 생성 vs 다운로드)
- 핀 스크립트 배포 위치와 버전 관리 방식
